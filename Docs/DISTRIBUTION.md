# macOS direct distribution

AnywhereHost is distributed as a standalone `.app`. The macOS application, Rust
service and frpc run without App Sandbox. App Store and TestFlight distribution
are not supported.

- Bundle ID: `com.jintongshu.AnywhereHost`
- Developer team: `775Y7KV7KU`
- Target: Apple Silicon, macOS 14 or later.

`AnywhereHost.xcodeproj` builds the SwiftUI application and embeds the Rust Host,
checksum-verified frpc, its license and the macOS application icon. The Swift
package is also available for source compilation.

## Build

```sh
./Scripts/build-app.sh
open dist/AnywhereHost.app
```

The script performs a clean Release build, assembles a fresh bundle in `dist`,
and signs both helpers and the application with Hardened Runtime. Local signing
defaults to ad hoc. `ANYWHERE_SIGNING_IDENTITY` selects an available signing
identity, including a Developer ID Application certificate for direct distribution.
Xcode uses manual ad-hoc signing by default; a signing identity can also be selected
in its build settings.

Developer ID notarization, stapling and automatic updates are not automated by
this project. The local ad-hoc build is for this Mac; it is not a notarized release.

## Execution and data

The app starts the bundled backend when setup begins on a fresh installation.
Existing configured installations continue starting the service while the new guide
is shown, using the user's existing Codex Home and login environment. Project folders, external volumes and toolchains do
not require Host folder grants. Codex receives native permission and approval
settings without Host overrides. macOS file permissions and privacy controls still
apply; the UI links to Full Disk Access when protected data is needed.

App and CLI state defaults to `~/Library/Application Support/AnywhereHost`.
There is no old-container lookup, data import or migration. Configuration, pairing
identity, events, tunnel settings and optional APNs keys all use this directory.

## Verification

```sh
python3 Scripts/verify-app.py dist/AnywhereHost.app --integration
```

The build script always verifies all three signatures, Hardened Runtime and the
absence of App Sandbox/inheritance entitlements or a provisioning profile. The
optional integration check starts the **packaged Rust executable** with disposable
state and a deterministic Codex peer. It exercises HTTPS/WSS, native permission
settings, approvals, files and process locking without using real credentials.

The icon is generated by `swift Scripts/render-icon.swift` and embedded as
`Resources/AppIcon.icns`.
